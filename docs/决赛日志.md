## 7-29
1. 为内核地址空间中所有线程的内核栈分配一个asid
    - 因此，创建新线程时，需要刷新这部分的asid
    - 多核记录自己的内核线程栈的数量，当数量发生变化时需要刷新内核栈的asid
    - 这样做可以防止tlb全量刷新，至少内核代码不用全量刷新
    - 同时，现在内核栈也有缓存机制，被释放的内核栈会优先用于新线程的内核栈分配
2. mmap现在是按需分配物理页，触发访址异常后才会分配物理页，复用写时复制逻辑
    - mmap分配的内存包括
        - 大块内存堆(即通过sys_mmap分配的内存)
        - 用户栈
3. futex在单核环境下，由于是并发执行，所以不会出现wake比wait早的情况，但当多核环境下，futex需要先拿到队伍锁在去判断信号量是否成立再入队，原来是先判断信号量的值再拿锁，会产生并发问题，例如：
    ```text
    错误流程（检查 futex 值与加入等待队列之间存在窗口）：

    CPU 0：FUTEX_WAIT                         CPU 1：线程退出 / FUTEX_WAKE
    ─────────────────────────────────────────────────────────────────────
    读取 futex，值仍等于期望值
                |
                |  尚未获取队列锁、尚未入队
                |                                  将 futex 修改为新值
                |                                  获取队列锁
                |                                  队列为空，唤醒 0 个线程
                |                                  释放队列锁
                v
    获取队列锁
    将当前线程加入等待队列
    释放队列锁并睡眠
                |
                v
    唤醒已经发生，不会再有人唤醒该线程，形成丢失唤醒（lost wakeup）。

    修复流程（在队列锁内二次检查并入队）：

    CPU 0：FUTEX_WAIT                         CPU 1：线程退出 / FUTEX_WAKE
    ─────────────────────────────────────────────────────────────────────
    获取队列锁
    在锁内重新读取 futex
    若值仍等于期望值，则加入等待队列
    释放队列锁并睡眠
                |                                  将 futex 修改为新值
                |                                  获取同一个队列锁
                |                                  从队列中取出并唤醒线程
                v                                  释放队列锁
    被正常唤醒

    若 CPU 1 先完成修改和唤醒，CPU 0 随后在队列锁内二次检查时会发现
    futex 值已经变化，因此不再入队睡眠，而是直接返回 EAGAIN。
    ```

## 7-30
1. 系统调用133：rt_sigsuspend，用临时mask替换原mask，并保存原mask，随后阻塞自己。
    - 常见用法：临时mask替换原进程mask，当自己的其它进程（例如子进程）退出或递送信号后会唤醒这个阻塞进程。
      - 注：这个阻塞进程不需要队列，只是变为阻塞状态
2. 修改：系统调用202：去除accept硬编码12秒
  - 原实现会在阻塞12秒后硬编码返回`EINTR`，但Linux阻塞式`accept`本身没有固定超时，因此删除该逻辑。
  - 为便于区分服务端死锁与正常等待连接，在阻塞式`accept`中加入低频心跳日志，持续输出监听状态。
3. 修改`exec`的脚本处理逻辑：
  - 内核读取首行`#!interpreter [optional-arg]`，加载shebang指定的解释器ELF，而不是在内核中解释或编译脚本。
  - 无shebang但文件名以`.sh`结尾的脚本仍用`/musl/busybox sh`。
  - 对解释器执行权限、文件类型和ELF格式进行检查，分别返回`EACCES`、`ENOENT`或`ENOEXEC`。
4. 修复`setup_oscomp_env()`遮蔽根文件系统目录的问题：
  - 原实现使用空Tmpfs覆盖`/bin`、`/sbin`、`/usr`、`/usr/bin`、`/lib`和`/lib64`，导致镜像中的`/bin/bash`不可见，并将`/usr/bin/env`替换成BusyBox applet。
  - 修改为优先复用镜像中的真实目录，仅在目录或命令缺失时创建Tmpfs节点或补充BusyBox applet，不再覆盖镜像原有程序。
5. 修复glibc动态加载器与`libc.so.6`版本混用：
  - 根文件系统与`/glibc/lib`包含两套不同版本的glibc。原`populate_lib_from_dentries()`无条件挂载兼容库，使用挂载点覆盖了根文件系统原有的动态加载器。
6. riscv的syscall 258：查询riscv硬件参数
7. 实现系统调用107：`timer_create`
  - `timer_create(clock_id, sigevent, timer_id)`用于创建POSIX定时器对象，并通过用户指针`timer_id`返回一个非负的`timer_t`。
  - 该系统调用只负责创建和登记定时器，不会立即启动计时；定时器的首次到期时间和重复周期应由后续的系统调用110：`timer_settime`设置。
  - 当前支持`CLOCK_REALTIME`和`CLOCK_MONOTONIC`两种时钟，以及以下到期通知方式：
    - `SIGEV_SIGNAL`：定时器到期时向所属进程发送指定信号。
    - `SIGEV_NONE`：定时器到期时不发送通知。
    - `SIGEV_THREAD_ID`：定时器到期时向所属进程内的指定线程发送信号。
  - 当用户传入的`sigevent`为空指针时，按照Linux语义默认使用`SIGEV_SIGNAL`并发送`SIGALRM`。
  - 创建时会检查时钟类型、用户指针、信号编号，以及`SIGEV_THREAD_ID`指定的线程是否属于当前进程；写回`timer_t`失败时会撤销已经创建的定时器。
8. 在`process/timer.rs`中新增POSIX定时器相关数据结构和全局注册表：
    - `KernelSigEvent`：与用户态`sigevent`交互的ABI结构，保存信号附加值`value`、信号编号`signo`、通知方式`notify`和目标线程ID `tid`。
    - `PosixTimer`：内核中的定时器对象，保存所属进程`owner_pid`、计时时钟`clock_id`、通知方式、信号编号、用户附加值和目标线程ID。
    - `POSIX_TIMERS`：以`timer_t`为键保存定时器对象的全局注册表
    - `NEXT_POSIX_TIMER_ID`：用于分配非负且当前未被占用的定时器ID。
    - 外部接口`add_posix_timer()`和`remove_posix_timer()`：封装定时器对象的登记与删除，系统调用实现仍保留在`syscall/process.rs`中。

    - 匿名 mmap 采用惰性分配，因此只有已经建立有效 PTE 的页返回驻留位 1；
    - 地址范围仍必须完整落在现有 VMA 中，否则按 Linux 语义返回 ENOMEM。
2. 调试并修复cagent-glibc测试中的多核TCP阻塞问题
  - 修复系统调用198：`socket`
    - TCP、UDP和Raw socket加入全局`SocketSet`与注册等待队列原先是两个独立步骤。多核下`net_poll()`可能在两步之间将尚未注册等待队列的`Closed` socket误判为孤儿并删除，随后通过旧handle访问时触发smoltcp panic：`handle does not refer to a valid socket`。
    - 现在统一按照`SOCKET_SET -> SOCKET_WAIT_QUEUES`的锁顺序，原子完成socket handle与等待队列的注册和注销，消除了无效handle竞态。
  - 修复系统调用203：`connect`
    - `TcpSocket::connect()`原先先持有`SOCKET_SET`，再获取`LO_IFACE`；服务端`accept`调用的`net_poll()`则先获取`LO_IFACE`，再获取`SOCKET_SET`。客户端与服务端并发时会形成ABBA死锁，表现为客户端永久停在`connect`、服务端永久停在`accept`。
    - 将`connect`统一为`LO_IFACE/NET_IFACE -> SOCKET_SET`的锁顺序，与`net_poll()`保持一致。
    - 将socket层的`connect`改为只启动TCP握手，阻塞等待、协议栈轮询和信号中断统一由系统调用层处理，删除内外两层重复等待。
    - 阻塞连接现在可以被`SIGALRM`、`SIGTERM`、`SIGINT`和`SIGKILL`中断并返回`EINTR`，避免timeout无法回收客户端。
    - 增加`[net/connect]`结构化日志，记录PID、fd、本地/远端endpoint以及`SynSent -> Established`状态迁移。
  - 完善系统调用200：`bind`和系统调用201：`listen`的调试
    - 确认服务端正确绑定`127.0.0.1:8080`并进入`Listen`状态。
    - 增加`[net/listen]`结构化日志，记录PID、fd、本地端口和监听状态。
  - 修复系统调用202：`accept`
    - 保持阻塞式`accept`没有内核硬编码超时的Linux语义，仅通过低频心跳输出当前TCP状态。
    - 修复后cagent运行中多组客户端均能完成`SynSent -> Established`，服务端的`accept`能够返回已连接fd；持续处于`Listen`表示当前没有新客户端，而非内核死锁。
  - 完善系统调用206：`sendto`
    - TCP/UDP发送后主动执行`net_poll()`推进smoltcp状态机和回环数据传递。
    - 增加`[net/send]`日志，记录请求长度和实际发送长度，用于确认HTTP请求是否完整发出。
  - 修复系统调用207：`recvfrom`
    - cagent客户端收到部分HTTP响应后会再次阻塞读取；timeout向客户端发送`SIGTERM`时，原TCP读取路径只检查`SIGALRM`，导致客户端无法退出，timeout和测试脚本一直等待，后续客户端也不会启动。
    - TCP阻塞读写现在同时检查`SIGALRM`、`SIGTERM`、`SIGINT`和`SIGKILL`，收到终止信号后返回`EINTR`，使timeout能够正常回收客户端并继续测试。
    - 增加`[net/recv]`日志，记录期望读取长度和实际返回长度，便于检查HTTP响应是否完整。
  - 修复多核日志按字符交错的问题
    - 恢复`CONSOLE_LOCK`，保证一次完整格式化输出在多核间原子写入，避免不同hart的PID、系统调用号和返回值被拼接成错误日志。
  - 验证结果
    - cagent测试能够完成多次TCP连接、HTTP请求和响应，并正常输出测试组结束标记，不再出现smoltcp panic、`connect/accept`死锁或客户端无法被timeout回收的问题。
    - 当前各cagent testcase仍可能输出`reject`，该结果属于用户态agent答案或测试判定问题；服务端内部的模板相似度只用于选择回答模板，不是内核测试得分。
3. 修复glibc墙钟时间接口
  - 系统调用169：`gettimeofday`原先错误返回开机后的单调时间，现改为返回Unix epoch墙钟，并补充空指针`EFAULT`检查。
  - 系统调用113：`clock_gettime`明确区分`CLOCK_REALTIME`与`CLOCK_MONOTONIC`，未知clock id返回`EINVAL`，不再静默按monotonic处理。
  - 该修改避免测试脚本混用两种时间纪元后得到约`±1.8e12 ms`的异常duration；若仍出现负Unix毫秒量级结果，应继续检查`date`子进程的clone、pipe、exec和wait链路是否丢失输出。
4. 修复TCP监听backlog与连接关闭语义
  - smoltcp单个TCP socket进入`SynReceived/Established`后不再保持`Listen`，无法独立实现POSIX backlog。为监听socket增加多个同端口handle，系统调用201按`backlog`创建最多32个监听槽。
  - 系统调用202扫描主handle和额外监听槽，accept后将已建立连接转移到新fd，并立即补充新的监听槽，减少并发连接收到RST或`ECONNREFUSED`的情况。
  - 修复系统调用201的自死锁：创建额外监听槽前先释放`SOCKET_SET`，避免`add_backlog_listener()`在同一hart上递归获取非可重入锁。
  - 修复最后一个socket文件引用关闭时直接删除smoltcp handle的问题。已建立连接现在先调用`close()`发送FIN，并加入`ORPHANED_TCP_SOCKETS`；进入`Closed`后再回收handle。
  - 该延迟回收保证HTTP客户端读取完header和body后，最后一次系统调用207能够稳定读到EOF，而不是一直等待到timeout信号打断。

  - 50: fchdir(): 将当前工作目录切换到文件描述符表中的文件夹
  - 223： fadvise64(): 为内核建议访问文件的模式。
7. 修复多核下管道读取将信号中断误判为EOF的问题
  - 问题表现
    - CAgent各测试虽然能够输出`pass`，但耗时会随机出现约`±1.78e12 ms`的异常值；正负数的绝对值恰好等于当前Unix毫秒时间戳。
    - 多核并发时异常方向不固定：开始时间为空会得到约`+1.78e12 ms`，结束时间为空会得到约`-1.78e12 ms`，两侧均为空时可能得到0。
  - 原因
    1. shell执行命令替换时会创建pipe，再经过`clone -> dup2 -> execve(/bin/date) -> write -> exit -> read -> wait4`取得子进程输出。
    2. 子进程退出产生`SIGCHLD`并唤醒父进程。原`Pipe::read()`在尚无数据时被任意未屏蔽信号唤醒，只要`check_pending_signal()`为真，就直接返回当前已读字节数。
    3. 当此时尚未读到数据，返回值就是0；但Linux中`read(pipe)`返回0只应表示所有写端均已关闭后的真实EOF。shell因此提前结束读取，把本次`date`输出解析为空。
    4. `File::read()`的返回类型是`usize`，本身无法表达`EINTR`，因此不能在原接口中区分信号中断和EOF。
  - 修复方案
    - 在`Pipe`上新增专用的`read_for_syscall()`，返回`Result<usize, Errno>`。
    - `sys_read()`通过`as_any()`识别pipe并调用该专用方法，其他文件类型继续使用原有`File::read()`，避免扩大接口修改范围。
    - 仅当pipe缓冲区为空且所有写端均已关闭时返回`Ok(0)`，保持0表示真实EOF。
    - 若阻塞等待被信号唤醒且尚未读取任何数据，则返回`EINTR`；若已经读取部分数据，则按照Linux短读语义返回已读取字节数。
    - pipe等待队列中的任务被唤醒后仍按TID移除残留等待项，随后重新检查数据、写端状态和信号，避免重复入队等。

#### 关于 tlb 刷新的时机
- 放宽权限和映射先前没有映射的旧页不用刷；
- 修改旧页数据或者释放旧页前要保证已经刷；
- 刷新正在使用该内存空间的 cpu 的指定区域 tlb 。
- 刷新本核时值刷新指定

为了可能减少刷新的浪费，用表维护了特定 satp 的活跃cpu 集合。每次切换 satp 先标记目标 satp 本核活跃，刷新 tlb 并切换 asid，再移除旧 satp 中的本核。这样做能确保某核完成页表修改，希望刷新指定 satp 时，在拿到锁获取刷新集合的瞬间，临界核或者已经自己刷过 tlb 切走，或者刚拿到该 satp（tlb还是空的，也相当于刷了一次）。而非临界核则根据活跃 cpu 集合正常失效相关表项。这能够保证在发起请求的核看来**所有 cpu 的相关 tlb 项，在刷新请求完成后，总是在获取到目标 cpu 集的锁的瞬间之后重新填充**
