## 7-22
开始加`-ual`参数没有生效（ds说默认就是-ual的，不过后来证明了实际上默认不是），以为是llvm bug，于是添加了core库源码到项目中并且修改core fmt部分源码，还构造了一条完整的符号链接系统rust工具链->编译库的流程。后来发现，-ual实际上对loongarch llvm是**有效的**，但core库不会自动重新编译（而是会使用预编译好的rlib文件，而这个rlib在龙芯平台上默认似乎以+ual编译）。

下面是对*默认含ual*的验证：

---
此猜想的验证过程如下（主要验证了先前出问题的core::fmt）:

先恢复仓库到原来的commit并恢复rust工具链为原版。
然后用默认的makefile编译一次：
```sh
RUSTFLAGS="-Clink-arg=-T$(LA_LINKER) -Cforce-frame-pointers=yes" LOG=$(LOG) INITPROC=$(INITPROC) BOARD=$(BOARD) cargo build --target loongarch64-unknown-none $(MODE_ARG)

```
反汇编fmt的elf发现（此处借助了llm进行定位）：
```S
9000000098003100 <core::fmt::write>:

#...

#偏移e4处
90000000980031e4: e4 03 15 00  	move	$a0, $s8
90000000980031e8: a0 0c 00 40  	beqz	$a1, 12 <core::fmt::write+0xf4>
90000000980031ec: c4 04 80 28  	ld.w	$a0, $a2, 1
```
与旧发现相符，**对某地址+1这样的地址直接使用ld.w**。

---

采用官方默认工具链，指定-ual，不指定build-std：
```sh
RUSTFLAGS="-Clink-arg=-T$(LA_LINKER) -Cforce-frame-pointers=yes -Ctarget-feature=-ual" LOG=$(LOG) INITPROC=$(INITPROC) BOARD=$(BOARD) cargo build --target loongarch64-unknown-none $(MODE_ARG)

```
可以发现库源码并不会重新编译。

---

在同样的环境下修改makefile指定-ual，并且指定build-std，再次编译:
```sh
RUSTFLAGS="-Clink-arg=-T$(LA_LINKER) -Cforce-frame-pointers=yes -Ctarget-feature=-ual" LOG=$(LOG) INITPROC=$(INITPROC) BOARD=$(BOARD) cargo build --target loongarch64-unknown-none $(MODE_ARG) -Z build-std=core,alloc,compiler_builtins -Z build-std-features=""

```
发现会报错找不到`rustc-literal-escaper 0.0.5`，这说明core库现在的确开始重新编译了，但依赖的crate不在vendor文件夹中。

取消对crates.io源使用vendor，重新编译。

---

总结就是：应该在使用`-Ctarget-feature=-ual`之后还应**使用`build-std`来重新编译标准库，保证编译参数对rust标准库生效**。
