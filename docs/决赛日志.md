## 7-29
1. 为内核地址空间中所有线程的内核栈分配一个asid
    - 因此，创建新线程时，需要刷新这部分的asid
    - 多核记录自己的内核线程栈的数量，当数量发生变化时需要刷新内核栈的asid
    - 这样做可以防止tlb全量刷新，至少内核代码不用全量刷新
    - 同时，现在内核栈也有缓存机制，被释放的内核栈会优先用于新线程的内核栈分配
2. mmap现在是按需分配物理页，触发访址异常后才会分配物理页，复用写时复制逻辑
    - mmap分配的内存包括
        - 大块内存堆(即通过sys_mmap分配的内存)
        - 用户栈
3. futex在单核环境下，由于是并发执行，所以不会出现wake比wait早的情况，但当多核环境下，futex需要先拿到队伍锁在去判断信号量是否成立再入队，原来是先判断信号量的值再拿锁，会产生并发问题，例如：
    ```text
    错误流程（检查 futex 值与加入等待队列之间存在窗口）：

    CPU 0：FUTEX_WAIT                         CPU 1：线程退出 / FUTEX_WAKE
    ─────────────────────────────────────────────────────────────────────
    读取 futex，值仍等于期望值
                |
                |  尚未获取队列锁、尚未入队
                |                                  将 futex 修改为新值
                |                                  获取队列锁
                |                                  队列为空，唤醒 0 个线程
                |                                  释放队列锁
                v
    获取队列锁
    将当前线程加入等待队列
    释放队列锁并睡眠
                |
                v
    唤醒已经发生，不会再有人唤醒该线程，形成丢失唤醒（lost wakeup）。

    修复流程（在队列锁内二次检查并入队）：

    CPU 0：FUTEX_WAIT                         CPU 1：线程退出 / FUTEX_WAKE
    ─────────────────────────────────────────────────────────────────────
    获取队列锁
    在锁内重新读取 futex
    若值仍等于期望值，则加入等待队列
    释放队列锁并睡眠
                |                                  将 futex 修改为新值
                |                                  获取同一个队列锁
                |                                  从队列中取出并唤醒线程
                v                                  释放队列锁
    被正常唤醒

    若 CPU 1 先完成修改和唤醒，CPU 0 随后在队列锁内二次检查时会发现
    futex 值已经变化，因此不再入队睡眠，而是直接返回 EAGAIN。
    ```

## 7-30
1. 系统调用133：rt_sigsuspend，用临时mask替换原mask，并保存原mask，随后阻塞自己。
    - 常见用法：临时mask替换原进程mask，当自己的其它进程（例如子进程）退出或递送信号后会唤醒这个阻塞进程。
      - 注：这个阻塞进程不需要队列，只是变为阻塞状态
2. 修改：系统调用202：去除accept硬编码12秒
  - 原实现会在阻塞12秒后硬编码返回`EINTR`，但Linux阻塞式`accept`本身没有固定超时，因此删除该逻辑。
  - 为便于区分服务端死锁与正常等待连接，在阻塞式`accept`中加入低频心跳日志，持续输出监听状态。
3. 修改`exec`的脚本处理逻辑：
  - 内核读取首行`#!interpreter [optional-arg]`，加载shebang指定的解释器ELF，而不是在内核中解释或编译脚本。
  - 无shebang但文件名以`.sh`结尾的脚本仍用`/musl/busybox sh`。
  - 对解释器执行权限、文件类型和ELF格式进行检查，分别返回`EACCES`、`ENOENT`或`ENOEXEC`。
4. 修复`setup_oscomp_env()`遮蔽根文件系统目录的问题：
  - 原实现使用空Tmpfs覆盖`/bin`、`/sbin`、`/usr`、`/usr/bin`、`/lib`和`/lib64`，导致镜像中的`/bin/bash`不可见，并将`/usr/bin/env`替换成BusyBox applet。
  - 修改为优先复用镜像中的真实目录，仅在目录或命令缺失时创建Tmpfs节点或补充BusyBox applet，不再覆盖镜像原有程序。
5. 修复glibc动态加载器与`libc.so.6`版本混用：
  - 根文件系统与`/glibc/lib`包含两套不同版本的glibc。原`populate_lib_from_dentries()`无条件挂载兼容库，使用挂载点覆盖了根文件系统原有的动态加载器。
6. riscv的syscall 258：查询riscv硬件参数
7. 实现系统调用107：`timer_create`
  - `timer_create(clock_id, sigevent, timer_id)`用于创建POSIX定时器对象，并通过用户指针`timer_id`返回一个非负的`timer_t`。
  - 该系统调用只负责创建和登记定时器，不会立即启动计时；定时器的首次到期时间和重复周期应由后续的系统调用110：`timer_settime`设置。
  - 当前支持`CLOCK_REALTIME`和`CLOCK_MONOTONIC`两种时钟，以及以下到期通知方式：
    - `SIGEV_SIGNAL`：定时器到期时向所属进程发送指定信号。
    - `SIGEV_NONE`：定时器到期时不发送通知。
    - `SIGEV_THREAD_ID`：定时器到期时向所属进程内的指定线程发送信号。
  - 当用户传入的`sigevent`为空指针时，按照Linux语义默认使用`SIGEV_SIGNAL`并发送`SIGALRM`。
  - 创建时会检查时钟类型、用户指针、信号编号，以及`SIGEV_THREAD_ID`指定的线程是否属于当前进程；写回`timer_t`失败时会撤销已经创建的定时器。
8. 在`process/timer.rs`中新增POSIX定时器相关数据结构和全局注册表：
    - `KernelSigEvent`：与用户态`sigevent`交互的ABI结构，保存信号附加值`value`、信号编号`signo`、通知方式`notify`和目标线程ID `tid`。
    - `PosixTimer`：内核中的定时器对象，保存所属进程`owner_pid`、计时时钟`clock_id`、通知方式、信号编号、用户附加值和目标线程ID。
    - `POSIX_TIMERS`：以`timer_t`为键保存定时器对象的全局注册表
    - `NEXT_POSIX_TIMER_ID`：用于分配非负且当前未被占用的定时器ID。
    - 外部接口`add_posix_timer()`和`remove_posix_timer()`：封装定时器对象的登记与删除，系统调用实现仍保留在`syscall/process.rs`中。
